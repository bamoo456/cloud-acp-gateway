這排 toolbar 是 mockup 的鷹架，不是要實作的 UI。v5 是照 production 程式碼重畫的，不是照 docs/ui-refactor/ 的 PNG——那些 PNG 是 mockup-b2 的截圖，其中 最左邊的 icon rail 與手機底部的 tab bar 從來沒有上線，v4 兩個都畫了。真實的 shell 是 #panel（284px）＋.content（header ／ .thread 760px 置中 ／ .dock 784px 置中 ／ footer）＋ #files（min(440px,34vw)），.statusbar 是 .app-row 的 sibling。token、圓角、類別名全部取自 web/src/styles.css。切 workspace · Agent 直接比對。

00v5 修掉了什麼

v4 是照 docs/ui-refactor/ 的 PNG 畫的，但那些 PNG 是 mockup-b2 的截圖，不是 app 的截圖。其中兩個元件從來沒上線：

  • 最左邊的 icon rail。真實的 .app-row 只有三個小孩：#panel、.content、#files。全域導航在 TopBar 的 .icon-btn 群。
  • 手機底部的四顆 tab bar。真實行為是 .app-row 在 860px 以下轉直排，一次顯示一個 pane，面板從 TopBar 下方浮出成卡片。

順帶修掉的還有：.idot 預設是 display:none（只有 data-identity="dot" 才畫），EngineDock 是兩顆 chip（permission mode 在左、engine 在右），.tool 圓角是 10px 而不是 16px，.composer 是 8px、底色 --surface-2，.statusbar 底色是 --surface-2，修改狀態的 .wf-mark 是 --accent 而不是 muted。

01Review 的進出點用既有的按鈕家族

TopBar 已經有 .sessions-btn 與 .files-btn 兩顆會亮的 .icon-btn。Review 就是第三顆，同樣的 30×30、同樣的 .on 樣式。不新增元件類型——v4 憑空長出一條 rail，正是我在 issue 上反對的那種做法。

另一個入口留在 #files 的 .wf-switch：那顆 Review tab 從「在面板裡渲染整個 review」變成切進 workspace，面板底部再放一顆 Open Review。.wf-badge 的數字沿用。

02Companion 是同一套 thread，不只是同一個元件

右欄的 turn 就是 .turn.user 與 .turn.agent：user 有 tint、邊框、16px 圓角與下方那條細線；agent 只有 .lbl（18px agent chip ＋ mono wordmark）加裸文字。字級小一號，因為欄窄。

Trace、review guide、圖表都是 details.tool——同樣的 .tkind 動詞、.ttitle、右側 .tstatus 讀數。它們是同一類東西：機器產生、可折疊、帶耗時。

抬頭寫「同一個 session」：MVP 共用實作 session，但 review 記錄存 agentName + sessionId，之後換成隱藏的 fork 不動任何像素。

03忙碌時排隊，比我上一版說的便宜

Composer 已經有 .queue-rail：虛線脊線加空心虛線節點，NEXT 1 與 SENDS IN ORDER, ONE PER TURN 兩行 mono 小標。styles.css 特別註記「說『還沒送出』的是那個虛線，不是一個顏色」——所以它不算第五種顏色。

這改了我在 issue 上的判斷：Queue 不是新工作，機制與視覺都在了，review 的 Ask/Fix 接上去就好。切 session busy · Queue 可以看到那條 rail 出現在 companion 的 composer 上方。

Disable 那一版仍然畫著，因為 ReviewPanel.tsx:70 現在就是那樣做。兩者的差別只剩「要不要接既有的 queue」。

04四種顏色，加一個記錄在案的例外

語意用在
ink／accent 可互動CodeRef、send／Ask、active 列的 inset 軌、reviewed 按下後
amber 需要你permission 左軌與 badge、changed-after-review、未解決討論
red／green只有 diff −／+，底色 rgba(…,.13)
muted 已完成已 review 的檔案、已解決的討論
--unread紅色但不是失敗——favicon 的 bitmap 已經把紅色花在「還沒讀」上
--pending 虛線還沒送出。用線型講，不佔一個顏色

推論出最違反直覺的一條：已 review 不是綠勾，是 muted 的 ✓。green 只代表 diff 的加行，而一整排綠勾會把真正沒讀的檔案淹掉。

05解不出來的 CodeRef 長什麼樣

companion 第三段的 AuthService.java 是純文字＋虛線底：撞名解不出唯一候選，所以連可點的樣子都不給。信任成本不對稱——一個看起來能點卻沒反應的 ref，會讓人不再相信同一段回覆裡其他真的能點的。

反過來，整份檔案層級的 ref 不需要行號（codeRef.test.ts 就是），path 必填、line 只在要精確定位時才要求。圖表同一條規則：虛線框的 node 不可點。

06Trace 是按鈕，不是 Cmd-click

Trace 在選取動作列裡，跟 Ask／Discuss／Fix 並排；回覆是 companion 裡一個 details.tool，.tstatus 印著 2.4s。

耗時是故意露出來的。agent 來回是秒級，Cmd-click 的預期是兩百毫秒內——綁上去會做出一個感覺壞掉的手勢，然後為了延遲而不是能力被迫提早上 LSP。

07討論在程式碼旁邊，不在 companion 裡

討論掛在某幾行上，跟 companion 的一問一答不同語意，所以內嵌在 diff 中，gutter 只留一個 ◆。框跟 details.tool 一致（10px 圓角、--surface-2 抬頭），因為它也是持久產物。

每則存下當時引用的那幾行（.rv-quote）。程式碼會動、行號會失效，引用不會——這正是既有 ReviewComment.code 在做的事，搬到 SQLite 時型別不必改。

跨檔案找未解決的討論走左欄第二個檢視，並沿用 .wf-badge 顯示數量。

08「在你 review 之後改過」怎麼講

橫幅只說發生了什麼與下一步，不提 turn、checkpoint、snapshot。判斷依據是內容 hash，而且是你當時螢幕上那一份的 hash，不是按下 Reviewed 時才去磁碟重讀的——差別在 agent 正好在你讀的時候改了檔案。

按鈕寫「重新 review」：第一版只標記並重開目前的 diff。比對「上次 review 之後多了什麼」要留著上一份內容，那是另一個 issue。

09中欄是唯一的檢視窗格

檔案檢視不是浮動視窗：#files 與 ReviewPanel 共用一個 .wf-view 與一個 store slot，後被要求的勝出（ReviewPanel.tsx:66）。在這個版面裡中欄就是那個窗格，所以 CodeRef、檔案列、trace 結果全部導航同一塊畫面。

代價是那個 slot 是全域的：切進 Review 時必須重新界定範圍或清掉，否則中欄會停在從 Agent Workspace 點開的無關檔案上。

10送出去的是什麼

composer 上那顆 chip 沿用既有的 .file-chip（Composer 本來就用它顯示 @ 引用的檔案與行段），印的是實際會送出的酬載：路徑、行號、diff 的哪一側、revision scope。加上當時的程式碼片段，缺一樣 agent 收到的行號就會指向另一棵樹。

只有請求真的被接受才清空輸入。送不出去卻清空會讓 no-op 看起來像成功——這個 codebase 已經被咬過一次，教訓記在 ReviewPanel.tsx:70。

11手機沿用既有行為，不新發明

issue 寫「Files / Companion 變成 sheets/drawers」，但真實 app 在 860px 以下已經有一套：面板從 TopBar 下方浮出成卡片（top:crumb-h+6px、左右 8px、16px 圓角、--shadow），Files 靠左最寬 460px、companion 靠右最寬 560px。所以這裡畫的是卡片，不是底部 sheet——同樣的效果，零新模式。

導航也沿用 TopBar 的兩顆 .icon-btn，不加底部 tab bar。.statusbar 在手機上把 .sb-diff 與健康的 connected 藏起來（真實 CSS 就是這樣）。

12還沒定的事

  • Fix 跑完之後停在哪：停在原位或跳到第一個改動。body 排除了「直接顯示新 diff」，但沒在前兩者之間選。
  • companion 收起後：中欄變寬，還是留白邊。
  • 忙碌時排隊還是停用：兩種都畫了。既有的 .queue-rail 讓排隊變便宜，但要決定排隊項目能不能取消、以及它算不算一個 turn。
  • file 模式的四顆動作：exploration 沿用既有的跨行文字選取，但 Discuss 掛在沒有 diff 的檔案上是什麼意思，沒畫。
  • Review 的 icon：現在是清單加勾，但它得跟 .files-btn 的面板圖示、statusbar 的分支圖示都分得開。
  • canvas 到底多寬：這裡用 268 ／ flex ／ 412，比真實的 284 ／ flex ／ 440 各縮一點來換 canvas 空間。要不要就直接沿用既有寬度、少一個要維護的數字，值得吵一下。
